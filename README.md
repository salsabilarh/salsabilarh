## Work Philosophy

**Clean Architecture over convenience.** Dependencies point inward — domain logic never knows about HTTP, databases, or frameworks. Every use case is independently testable. This is not a preference; it is how I write code by default.

**Test coverage as a design signal.** Writing tests after the fact is documentation. Writing them before or alongside reveals design problems early — when they are cheap to fix. 100% coverage on 53 test files in Forum API was not the goal; it was the outcome of writing testable code from the start.

**Documentation is part of the deliverable.** Code that works but cannot be maintained is a liability. Every numbered fix (`#14`, `#25`), every `constants/index.js` as a single source of truth, every JSDoc comment explaining *why* — these reduce the cost of the next developer's first day on the codebase, including future me.

**Performance decisions need evidence.** LRU cache TTL of 5 seconds was not arbitrary — it balances DB hit reduction against acceptable staleness. 300+ concurrent user validation via JMeter was not optional — it was how I confirmed the system held before claiming it did.
